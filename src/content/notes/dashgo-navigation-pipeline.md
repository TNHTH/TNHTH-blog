## 为什么要拆成链路

学习式导航最容易出现的问题，不是某个算法名写错，而是训练时的观测、动作和真实运行时不一致。把系统拆成链路，可以让每一段都有自己的检查点。

```text
仿真环境 → 观测编码 → 策略训练 → 模型导出 → 导航运行时 → 评估
```

## 1. 环境与机器人模型

首先要明确机器人、传感器、障碍物和动作接口。环境中的坐标系、传感器范围、控制频率和动作限制，都会影响策略最终学到的行为。

## 2. 观测与策略

观测把激光雷达、目标信息和机器人状态整理成策略可以使用的输入。策略再把输入映射到连续动作。这里最重要的不是堆更多输入，而是保证训练和运行时对每个字段的含义保持一致。

## 3. 导出与运行时

训练完成后，模型需要进入一个更小、更可控的运行时。导出格式、输入归一化、动作裁剪和异常处理都应该单独验证，不能把“训练脚本能运行”当成“机器人可以执行”。

## 4. 评估与边界

评估至少要区分：到达目标、碰撞、轨迹质量、推理延迟和失败原因。一个阶段性实验可以证明链路打通，但不能自动推出稳定部署或泛化能力。
